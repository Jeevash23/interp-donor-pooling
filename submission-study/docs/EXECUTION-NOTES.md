# Execution record

The earlier pilot is preserved in the parent project. This extension is a new experiment with separate data and a prospectively specified protocol. It was designed after seeing pilot outcomes; it is not an independent replication of a publicly preregistered hypothesis.

## Before test evaluation

- Primary models were chosen from cached checkpoints before extension outcomes. All data were generated without model outputs. The generator rejected candidates only for exact-string overlap or tokenizer/annotation constraints; counts are in `data/generation-audit.json`.
- On 12 September 2026, the first Pythia calibration launch stopped before a forward pass because Transformers 5.16.1 names its output projection `lm_head`, whereas older versions used `embed_out`. The adapter was changed to the public `get_output_embeddings()` accessor. This affects only the GPT-NeoX branch. Failed logs are preserved with `attempt1` in their names. No primary evaluation had begun, no tolerance changed, and no model was dropped.
- The BLiMP subset has disjoint nine-prefix clusters. Each cluster supplies nine rotating recipients and eight other prefixes as donors; all nine measurements stay together in uncertainty estimation. It is a next-token contrast assay on a subset of one BLiMP paradigm, not the official whole-sentence benchmark score.
- Two attempted public metadata URLs returned 404 (BLiMP `LICENSE`, TMLR `tmlr.tex`). The actual BLiMP license is stated in its README; the official TMLR example is `main.tex`. Provenance records retain the failed requests and successful sources.

Development outcomes are allowed for engineering and evaluating whether exploratory baselines are useful. The main test estimands, tolerances, model list, tasks, sites and materiality thresholds remain those in the prospective protocol.

- Before test evaluation, validation version 2 explicitly records probability errors for native, readout and identity comparisons and head-slice write equality, enforcing the already specified probability tolerance. Earlier GPT-2 calibration files are retained as version 1 and those gates are repeated before evaluation. Development measurements are unchanged.
- Before test evaluation, the finite-bank baseline enumeration was expanded to all 56 five-of-eight subsets as well as all 70 four-of-eight subsets. Five samples exactly match the correction's five intervention forwards. This is an additional descriptive comparison, computed from the same eight measured donor outcomes, with no extra inference or primary-claim change.
- Pythia's first numerical calibration at maximum batch size 16 failed the fixed 0.001 full-vocabulary logit tolerance (maximum 0.00195885). A calibration-only sweep of batch sizes 1, 2, 3, 4, 8 and 16 isolated shape-dependent arithmetic: singleton execution gives exactly zero native and identity disagreement across all three inspected tasks, while multi-example execution does not meet the gate on KV. Pythia therefore uses batch size 1 in the main, head, external and precision runs. This is within the protocol's at-most-16 limit. Tolerances were not relaxed. The failed calibration and complete sweep are retained; no test outcome informed this choice.

## Reporting audit during test execution

- On 12 September 2026, after the Small and Medium test results and while Large was running, source/data inspection clarified the protocol's phrase “two held-out paraphrases.” These templates were held out only as development recipients: broad donor generation has always sampled all four templates. The frozen protocol and generator are preserved. The manuscript and table labels now say recipient-template transfer and explicitly disclose exposure through broad development donors. No data, endpoint, threshold, measurement or frozen analysis is changed. The existing `heldout_template` field marks recipient-role exclusion only. No globally unseen-template claim is made.
- Calibration reserves four groups per task but the gate actually uses the first group from each task (three groups total). The manuscript now states that count and distinguishes the remaining unused calibration groups from the checks performed in every evaluated group.
- Corrupted-input pair scores retain the original clean target, so they are labeled clean-target preference rather than accuracy against a relabeled corrupted answer.

## Supplementary CPU execution, specified before those outcomes

- While the primary GPU panel was running, the already available CPU was calibrated using the unchanged gate implementation and reserved calibration cases. GPT-2 Small passed (maximum logit error 0.0000991821, target-probability error 0.00000778004). The planned BLiMP and attention-head assays are now assigned to a separate CPU worker so they can progress alongside the primary GPU panel. Every model must first pass its own CPU calibration at the original float32 tolerances. Scientific inputs, conditions, scoring, analysis, sample sizes, and the frozen assay/engine files are unchanged; the wrapper overrides only the execution device. This hardware decision occurs after the three GPT-2 primary results were available and before any external/head outcome. CPU replay uses a freshly loaded CPU model. Device records and CPU calibration outputs are separate from primary GPU environment records. Any CPU failure stops the worker and is preserved.

- After measuring CPU throughput on the first BLiMP panels, scheduling was refined before any head evaluation: BLiMP remains on CPU, and all three attention-head panels remain on GPU. The CPU coordinator was paused while its Medium child continued to completion; no model measurement was interrupted. A new CPU-only BLiMP coordinator then resumes the remaining panels, preserving the original wrapper/batch bytes and their earlier freeze. `data/cpu-scheduling-v2.json` records this device-only revision. Head conditions, cases and analysis are unchanged and use the original GPU supplementary runner.

- Pythia's CPU calibration failed before any BLiMP measurement: the maximum duplicate-donor discrepancy was 0.0025391579 logits, above the unchanged 0.001 gate; target-probability error was 0.00000110672. The failed CPU calibration is retained. Pythia BLiMP is assigned back to its already validated GPU configuration, while the remaining CPU-capable panels continue. No model or test group is dropped. The numerical tolerance and scientific implementation are unchanged. `data/cpu-scheduling-v3.json` freezes the scheduling revision before any Pythia BLiMP outcome.

- A calibration-only numerical diagnosis of the failed Pythia CPU duplicate control at KV/block17/END found a 9.536743e-7 source-vector change from float32 averaging eight identical vectors and the same 0.002539158 logit discrepancy. Computing only that diagnostic mean in float64 and casting back gives exactly the original vector and zero output discrepancy. This explains the failure without changing the scientific mean operator or the failed gate. The diagnostic script and output are retained; it is not a new test-set method or a tolerance amendment.

## Delivery analysis details

- Before head-panel outcomes, `audit_rank_stability.py` implements the protocol's requested aggregate bootstrap sign-support check for the saved head responses. Residual-pair intervals already come from the frozen primary analysis. The new head intervals use the same 20,000 seed-stratified group resamples, are pointwise 95%, and do not imply simultaneous significance or circuit discovery. Its source and timing are recorded in `data/rank-audit-timing.json`; primary results were already available.
- Reporting scripts also retain the maximum identity-margin discrepancy from the already-recorded bfloat16 audits. Those diagnostics use the separately specified reduced-precision calibration gates; they do not enter or alter the float32 primary family.

## Reduced-precision calibration amendment

- The first bfloat16 gate, GPT-2 Small at the default maximum batch of 16, failed before any reduced-precision test case: 1.5 logits and 0.062262 target-probability discrepancy, against the unchanged 0.5/0.05 gates. The largest failures are identity comparisons under differing batch shapes. The failed gate, environment and original logs are preserved.
- Before reduced-precision test outcomes, `data/bfloat16-batching-amendment.json` specifies one bounded fallback for each bfloat16 checkpoint: default batching, then singleton execution if that calibration fails. Both use the same three reserved calibration groups, fixed numerical gates and frozen implementation. A failed singleton gate still prohibits evaluation. Selected batch sizes are reported for both precisions; these are numerical-configuration comparisons rather than a claim isolating dtype from every kernel-shape effect.

- Singleton GPT-2 Small removes the identity/native discrepancies but still fails the original gate because reconstructing all final states in a multi-row readout differs by up to 1.0 logit. A calibration-only diagnostic evaluates the same frozen readout one row at a time: native/identity/readout discrepancies become zero, and the remaining maximum is 0.1875 from quantized mean-logit endpoint closure, within the original 0.5 gate.
- Before any bfloat16 test measurement, `data/bfloat16-readout-amendment.json` freezes a reduced-precision-only adapter. It calls the original readout unchanged whenever its input has one row, as every scientific mean-state endpoint does, and splits only multi-row reconstruction calls. Default native batching is tested first, with singleton fallback when required by the same calibration gates. Both earlier failures and the passing diagnostic are preserved. This is a documented numerical execution change; no mathematical operator, mean construction, metric, threshold, input case or primary float32 result is changed.

## Completed reduced-precision outcome and interpretation

- The Qwen3-1.7B calibration passed, and all 288 test groups plus the fixed replay completed. Full-test diagnostics nevertheless show identity-margin errors up to 1.875 logits and direct pooling gaps up to 0.3828125 logits at terminal ANCHOR, a structural null. Of 2,304 group/site audit records, 49 exceed a descriptive half-logit identity-margin reference. This reference is reported after the run; the frozen runner did not enforce a bfloat16 per-test identity threshold. No test cases are removed, no tolerance is changed, and no improved configuration is selected from these outcomes.
- The larger run is retained as a numerically limited diagnostic, not a successful robustness or scaling replication. Its confidence intervals quantify variation over groups conditional on the executed configuration; they do not absorb numerical error. The six validated primary float32 checkpoints remain the basis of the boundary claims.
- The execution ledger covers planned study runs and their fixed replays. Later portable-launcher and archive-integration reruns are logged separately and do not change the experimental sample sizes.
